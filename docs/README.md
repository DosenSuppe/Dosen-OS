# Dosen-OS Documentation

Dosen-OS is a small operating system for my custom **32-bit CPU**, which runs on
a byte-addressed software emulator (the toolchain lives in the
[CPU-24bit project](https://github.com/DosenSuppe/CPU-24bit)). It boots into an
interactive shell with a persistent file system, keyboard input, TTY output, a
framebuffer with a small graphics library, a cooperative process model, and a
runtime program loader.

The OS is written in a mix of **DASM** (Dosen-Assembly) and **C**. The C is
compiled to DASM by an external compiler (`dasm-cc` / `cc.py`); each `*.c`
source has a generated `gen-*.asm` next to it. The whole thing is assembled and
linked into a single C32R image (`os.bin`) that the emulator loads.

## Feature overview

- **Persistent file system** backed by an MMIO "PermaStorageDevice" that the
  host auto-flushes to real files (shared with the host filesystem via the
  emulator).
- **Drivers** for the emulator screen (320×200, 24-bit RGB), the TTY, and the
  keyboard.
- **Graphics library** (pixels, rectangles, circles, sprites, double
  buffering) in [ScreenDriver.c](../src/drivers/ScreenDriver.c).
- **Cooperative foreground-process model**: programs push themselves onto a
  process stack and get driven by the kernel dispatch loop; ESC/exit pops back.
- **Runtime program loader**: built-in commands and loadable programs share a
  single registry and a versioned program ABI.
- **"DIBmap"** (Dosen Interpreted Bitmap) image support, with a bitmap font.

## Bundled programs

- `pong` 
- `dibmap`
- `fontwriter`
- `edit`

See [Programs](./Programs.md) for details. Any of these (and the commands above)
runs via the shell's implicit `run` prefix; typing `pong` is the same as
`run pong`.
